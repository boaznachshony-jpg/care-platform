You are a senior product designer, UX architect, frontend engineer, and privacy-aware prototype builder.

Build a polished, interactive, mobile-first web prototype for a product called “CareDesk Israel”.

PRODUCT PURPOSE
CareDesk Israel is a digital assistant for Israeli families that directly employ a foreign live-in caregiver for an elderly or disabled family member.

The product is not merely a document repository or payroll calculator. It should behave like a calm, proactive employment manager that tells the user:
1. What is urgent?
2. What is coming up?
3. How much should be paid?
4. What information or document is missing?

The first target user is a son or daughter managing one caregiver for one care recipient.

PROTOTYPE GOAL
Create a realistic clickable prototype for user testing, not a production system.

The prototype must:
- Be in Hebrew.
- Use full right-to-left layout.
- Be mobile-first and responsive for desktop.
- Use synthetic demo data only.
- Never ask the tester to enter real passport, bank, medical, or identity information.
- Simulate document upload, payroll calculation, task completion, timeline updates, and AI answers.
- Preserve state during the prototype session.
- Look trustworthy, calm, modern, accessible, and simple.
- Avoid the visual style of a government website or legacy payroll system.

TECHNOLOGY
Use React with clean component structure.
Use local state or mock JSON only.
Do not connect to a real backend.
Do not use real authentication, payment, OCR, government APIs, email, SMS, or AI APIs.
All sensitive functions must be simulated.
The prototype should be self-contained and runnable in the artifact environment.

PRIMARY USER JOURNEY
The prototype must support one complete clickable story:

1. User enters the demo.
2. Dashboard clearly shows that visa renewal is the next urgent action.
3. User clicks “מה עליי לעשות עכשיו?”
4. User opens the visa-renewal task.
5. User sees a simple explanation, required items, and privacy reassurance.
6. User simulates uploading a new visa document.
7. User reviews extracted demo fields:
   - Visa type
   - Visa number
   - Expiry date
8. User confirms the document.
9. The urgent task becomes completed.
10. Dashboard updates immediately.
11. User opens July payroll.
12. User goes through a short payroll wizard:
    - absence / leave
    - Saturdays and holidays
    - additions and deductions
13. User reviews a transparent payroll breakdown.
14. User approves the demo payroll.
15. User simulates attaching a bank-transfer confirmation.
16. Payroll is marked as paid.
17. Care Timeline updates with visa renewal and payroll payment.
18. User opens the smart assistant and asks:
    “מה נשאר לי לעשות החודש?”
19. Assistant answers using only the demo case:
    - No urgent tasks
    - Medical insurance renewal in 112 days
    - Next payroll date
20. User sees a trial/pricing screen for willingness-to-pay testing.

SMART ASSISTANT
The prototype assistant is simulated and must never present itself as a lawyer, accountant, doctor, or government authority.

Suggested buttons:
- כמה לשלם?
- מה חסר?
- מה דחוף?
- מצא מסמך
- בדוק זכויות
- צור מכתב
- מה נשאר החודש?
- שאל שאלה

Every answer card must include:
- Direct answer
- Recommended next action
- Source label, for example:
  “מקור: נתוני תיק ההעסקה והכללים המאושרים”
- Confidence:
  “ודאות גבוהה”, “ודאות בינונית”, or “נדרשת בדיקה”
- Disclaimer:
  “המידע הוא תפעולי ואינו מהווה ייעוץ משפטי, חשבונאי או רפואי.”
- Action button where relevant

The assistant must refuse or escalate:
- Final legal interpretation
- Medical decisions
- Whether to dismiss the caregiver
- Definitive eligibility decisions
- Final settlement approval
- Attempts to bypass legal or reporting obligations

Example refusal:
“לא ניתן לקבוע זאת באופן סופי מתוך נתוני התיק בלבד. מומלץ להעביר את המקרה לבדיקה מקצועית.”
